# Androsaur: что уже сделано (контекст для ИИ-агентов)

Состояние на 2026-10-24. Документ описывает три работающих приложения и то, как они связаны. Цифры измерены на одном телефоне
(Xiaomi Redmi 12, Android 15, MIUI); на других телефонах ничего не проверялось. Решения владельца проекта (что считается утверждённым,
что нет) лежат в `androsaur-brief.md` в его рабочем пространстве, не в GitHub; всё, что ниже названо «гипотезой» или «не проверено»,
решением не является.

## Что это

Голосовой домашний ассистент из старых Android-телефонов, который в итоге стоит на моторизованной подставке: просыпается по слову,
поворачивается к человеку, видит, слушает и разговаривает. Построен как «колония» маленьких приложений на одном телефоне: каждое можно
использовать отдельно, у каждого свой HTTP-сервер и MCP-сервер прямо в приложении (без облака). «Петя» — имя персонажа, а не название
продукта; сейчас в проекте стоит пробная фраза «железяка». GitHub-организация `androsaurs`.

| Репозиторий | Приложение | Пакет | Порт | Роль |
| --- | --- | --- | --- | --- |
| `androsaur` | Androsaur | `dev.hram.androsaur` | нет | лицо на экране, «мозг», запускает модули |
| `androsaur-audio` | Androsaur Звук | `dev.hram.androsaur.audio` | 8089 | микрофон, wake-word |
| `androsaur-camera` | Androsaur Камера | `dev.hram.androsaur.camera` | 8088 | камера, слежение за лицом, узнавание людей |
| `androsaur-stand` | не создан | | | подставка с ESP32 (планируется) |

Общие правила всех модулей: микрофон читает только `androsaur-audio`, камеру держит только `androsaur-camera`; главное приложение
ничего не снимает и не слушает, оно запускает модули и опрашивает их. Фоновая работа не решена (см. «Не сделано»).

## Как приложения связаны

- **Транспорт:** обычный HTTP/1.1 (свой ограниченный сервер, закрыт `Origin` на `/mcp`) и MCP по Streamable HTTP (один JSON-ответ на POST,
  `POST /mcp`, без сессий и SSE). Каждый запрос требует `Authorization: Bearer <токен>`. Токен — учётные данные: не печатать, не логировать.
- **Объявление в сети:** mDNS `_androsaur-audio._tcp`, `_androsaur-camera._tcp` (поиск пока никто не написал).
- **Доверие между приложениями:** все APK подписаны одним ключом; у каждого модуля сигнатурное разрешение
  `dev.hram.androsaur.<audio|camera>.permission.CONTROL`. Модуль отдаёт порт и токен провайдером `content://dev.hram.androsaur.<audio|camera>.link`
  (вызов `link`) только приложению с той же подписью; сервис модуля тоже экспортирован под этим разрешением. Модули надо ставить на телефон
  раньше главного приложения.
- **Сценарий:** главное приложение на экране → получает токены → запускает сервисы звука и камеры (видимое приложение может это делать из
  переднего плана на Android 15, проверено) → опрашивает `/status`, `/events`, `/faces`, `/people` раз в 250 мс.

## androsaur-audio: звук и wake-word

Foreground-сервис с микрофоном (`AudioRecord` 16 кГц, моно, кадр 32 мс). Распознаёт ключевую фразу сменным движком и пишет события в журнал.

**Движки** (выбор и настройка через API, сохраняется): `none`; `vosk` (русская модель `vosk-model-small-ru-0.22`, свободное распознавание,
фраза ищется в тексте с допуском на искажения слов); `vosk-grammar` (грамматика из одной фразы, срабатывает на любое «привет …», оставлен для
сравнения); `mww:okay_nabu`, `mww:hey_jarvis`, `mww:hey_mycroft` (microWakeWord, TFLite Micro, английские модели; русской модели нет).

**Ключевая фраза** меняется через API: русские буквы, 1–4 слова, варианты через `|`, допуск `~N` (0–3 правки, первая буква та же):
`привет|здравствуй петя~1`. Умолчание `привет~3 петя~1`; на телефоне сейчас `железяка~1`. Для `mww:*` фраза зашита в модель. Для длинного слова допуск
ставить 1: при 2 «железа» принималось за «железяка».

**HTTP:** `GET /status`, `GET /events?after=<id>`, `POST /engine` `{engine?, phrase?}`, `POST /mcp`.
**MCP-инструменты:** `status`, `recent_events`, `set_engine` (engine и/или phrase), `simulate_wake` (то же событие без голоса, для тестов).
**События** (`/events`): `service_started`, `engine_ready`, `engine_failed`, `wake_word` (`engine`, `heard`, `levelDbfs`), `heard` (текст
фраз с началом слов фразы, для подбора допусков), `microphone_silent`/`microphone_recovered`, `error`. Журнал в памяти, сбрасывается при
перезапуске. `status` содержит `engine{id,state,msPerFrame,available}`, `microphone{levelDbfs,silent}`, `phrase`, `latestEventId`.
**Экран приложения:** кнопки движков, зелёная вспышка при срабатывании, шкала уровня микрофона, текущая фраза.

**Измерения (5 фраз и 30 с речи, один говорящий):** `vosk-grammar` 3/5 без ложных; `okay_nabu` 3/5; `hey_mycroft` 3/5; `hey_jarvis` 0/5.
Процессор на кадр 32 мс: microWakeWord ≈5% ядра, Vosk с грамматикой ≈9–22%, свободный Vosk ≈22–39%. Свободный Vosk слышит «привет» как «пред»
(поэтому допуск 3). Фраза «железяка~1»: 5 из 5 и 6 из 6 распознана, «железо», «железа», «железная дорога» отсечены; «привет всем» и «привет как дела»
(фраза «привет петя») не срабатывали (0 из 4, выборка малая). Porcupine отпал (бесплатный тариф закрыт 30.06.2026). Свою русскую модель microWakeWord не обучали.

## androsaur-camera: камера, лицо, люди

Foreground-сервис с камерой на CameraX. Выросла из документ-камеры для paper-ledger (бывший `mobile-ledger`, перенесён целиком с историей):
сканерные части (`/capture`, `/result`, `/ack`, калибровка по QR, фокус «только по запросу») сохранены, но работают только с задней камерой.

**Камера:** по умолчанию **фронтальная** (`lens: front`, на Redmi 12 8 Мп, штатный фокус, вспышки нет, кадры не отзеркалены); выбор
`POST /camera {lens}` или MCP `set_camera`, сохраняется. При `front` сканер (не от MCP-агента), калибровка и `focus` отвечают
`front_camera_selected`. Камера отпускается через 15 с без обращений, пока не включено слежение или экран.

**Слежение за лицом** (`GET|POST /faces`, MCP `face_lab`): три детектора на одних кадрах 480×640 (чип камеры Camera2 SIMPLE; ML Kit Face
Detection; MediaPipe BlazeFace) и MediaPipe Face Landmarker (478 точек, поза головы). Режимы: A чип, B +ML Kit, C +MediaPipe (**умолчание**),
D все три, E +Landmarker. Рамки наклоняются по углу головы. Отдаёт только числа (рамка как доли 0–1 прямого незеркального кадра, наклон,
оценка); кадры наружу не уходят, пока агент сам не просит `preview`/`take_photo`.

**Люди и узнавание** (экран «Люди», `GET /people` и `/who`, `POST /people/identify|rename|forget`, MCP `people`, `identify`, `rename_person`,
`forget_person`): обучение делается **только на телефоне** (до 12 снимков при разных положениях головы, один человек в кадре), проверка видит до
3 лиц с подписью и сходством. Цепочка: Landmarker даёт 5 точек (зрачки, нос, уголки рта) → лицо выравнивается на шаблон 112×112 → SFace
(OpenCV Zoo, int8, Apache 2.0, ONNX Runtime) → 128 чисел → косинусное сходство, у человека среднее трёх лучших образцов, порог по умолчанию 0,40
(регулируется на экране). Хранятся **только векторы** в `files/people/people.json`, фотографии никогда. `POST /people/identify {ms}` (0,5–10 с)
включает распознавание на окно поверх слежения и снова выключает; результат читается через `/people` (`who` для самого крупного лица, `faces`
для всех) и исчезает через 1,5 с после окна.
**MCP-инструменты всего модуля:** `status`, `preview`, `take_photo`, `view_capture`, `view_region`, `get_capture_link`, `list_captures`,
`get_capture_info`, `release_capture`, `set_camera`, `face_lab`, `people`, `identify`, `rename_person`, `forget_person`, `torch`, `focus`.
Изображения агенту не отдаются без запроса, ссылки `/dl/` — учётные данные (не печатать).

**Измерения (один человек лицом):** ML Kit ≈91 мс на кадр (≈10 кадров/с); MediaPipe BlazeFace ≈26–33 мс плюс ≈10 мс преобразования кадра
(≈20 кадров/с), лицо в 96–100% кадров; Landmarker ≈67 мс плюс ≈10 мс; чип камеры не нагружает процессор, но находит лицо нестабильно
(25–98% кадров); центры рамок всех детекторов совпали. Узнавание: поиск лица ≈90 мс, вектор SFace ≈67 мс, ≈9 кадров/с на одном лице; первое имя ≈1,3 с
после запроса при холодных моделях, ≈2,5 с от фразы до имени на экране при прогретых. Профиль, 2–3 м, пустой кадр и три лица не замерены.
Известное: APK ≈105 МБ (две библиотеки детекции, ONNX Runtime, модели), только arm64-v8a и armeabi-v7a.

## androsaur: лицо и «мозг»

Одно приложение на весь экран (экран не гаснет, системные панели скрыты, можно выбрать как «Домашний экран»). Рисует лицо: глаза и рот.
- **Рефлексы без LLM** (чистая логика в `shared`, с тестами): фраза даёт открытый рот и широкие глаза на 3 с; лицо в кадре даёт внимательный
  взгляд и улыбку, зрачки следят за лицом (поправка на зеркальность экрана); две минуты тишины дают сонные веки; раз в 30 с картинка сдвигается
  (защита AMOLED от выгорания).
- **Имя по фразе:** по событию `wake_word` приложение просит камеру опознать лица на 3,5 с, берёт самое крупное и рисует имя под лицом
  (или «Не узнаю»). Имя держится 10 с после последней фразы, пропадает сразу, если человека нет в кадре дольше 4 с.
- **Само подключается при старте:** запускает оба сервиса, включает слежение; следит, чтобы сервисы отвечали, и перезапускает молчащий
  (не чаще раза в 15 с); если камера забыла слежение, включает его снова. Панель со статусами скрыта, касание по лицу показывает её.
- Что **не** делает: не говорит, не использует LLM, не управляет подставкой, не умеет возвращать модули, когда само не на экране.

## Как собирать и проверять

Везде одинаково: Kotlin 2.1.20, AGP 8.7.3, Gradle 8.10.2, compileSdk 35, minSdk 26, KMP-модуль `shared` (общая логика с тестами) + `androidApp`.
`ANDROID_HOME=$HOME/Android/Sdk ./gradlew :androidApp:assembleDebug :shared:jvmTest :androidApp:lintDebug`. Для звука нужны NDK 29.0.14206865 и CMake 3.22.1.
Модель Vosk в git не лежит (скрипт `scripts/fetch-vosk-model.sh`). Каждый репозиторий содержит `AGENTS.md` (правила) и `README.md`.
Проверка с компьютера: `adb forward tcp:18088 tcp:8088` (камера) и `tcp:18089 tcp:8089` (звук); токен читать из `shared_prefs` приложения
(`run-as`, не печатать). Особенности MIUI: новый пакет `adb install` не ставит без подтверждения на экране (положить APK в `Download` и поставить
руками), `adb shell input` запрещён, обновление пакета убивает сервис, и Android сам его не возвращает.

## Не сделано и не проверено (не считать решённым)

- **Фон:** на Redmi 12 после убитого процесса сервис модуля сам не возвращается; главное приложение возвращает его только пока оно на экране.
  Перезагрузка, ночь с выключенным экраном (Doze), исключения батареи MIUI не проверены.
- **Нет:** речи и LLM, управления подставкой (ESP32; идея на потом: ESP32 как ADB-хост по USB или BLE-привязка), поиска модулей по mDNS,
  потоковых событий (сейчас опрос), модулей на другом телефоне, русской модели wake-word «Привет, Петя», общей библиотеки `androsaur-protocol`.
- **Не проверено:** узнавание на чужих лицах (какой порог разделяет людей), три лица в кадре по скорости, профиль и дальняя дистанция,
  реальный голос с главным приложением (проверялась имитация `simulate_wake`), другие телефоны.
- Открытые вопросы владельца: где живёт LLM, кто управляет сервоприводами, нужен ли автозапуск без человека, итоговый движок wake-word и детектор лица.
